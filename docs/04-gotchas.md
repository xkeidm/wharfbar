| Hızlı ayarlar / PolicyConfig | Varsayılan ses aygıtı için `IPolicyConfig` (ADR-006); tepsi RPM değil |
| Ses karıştırıcı | Tek seçili çıkış aygıtı + satır içi expander ile varsayılan değiştirme (QS `Popup` içinde iç içe `Popup` kullanma — odak kaçar, liste görünmez); master `IAudioEndpointVolume` + oturum listesi; `IMMDeviceCollection` IID `…8397-CC5392387B5E`; `IAudioSessionEnumerator` ComImport’u IUnknown IID ile sar (resmi IID QI `E_NOINTERFACE` verir, vtable yine enumerator); oturum slider sürüklerken satırları yeniden kurma (poll/`Changed` mid-drag UI’yi yıkıyordu); oturum ikonu süreç yolu yoksa MDL2; UWP ikonları sınırlı (ADR-006) |

| `SystemThemeWatcher` istenen backdrop’u ezer | Watcher varsayılan Mica basar; tema mesajlarını `WindowAppearance.Refresh` ile işle |
| `ContextMenu`/`MenuItem` stilini `BasedOn` olmadan yeniden tanımlama | WPF-UI Fluent şablonları düşer; Aero2 açık gri ikon sütunu + koyu menü gövdesi → `SymbolIcon` kaybolur. `App.xaml`’de `UiContextMenu` / `UiMenuItem` / `WpfUiMenuItem` üzerine BasedOn; yalnızca font ayarla |
| Kenar şeritte yuvarlak DWM köşe | DWM dört köşeyi birden yuvarlar; üst bar `DONOTROUND` |

| Sistem / yabancı tepsi ikonlarını okumaya çalışma | ADR-009: yalnızca belgelenmiş comctl32 `TB_*` mesajlarıyla salt-okunur ayna + `SendMessage` click-forward; `ToolbarWindow32`/RPM/enjeksiyon yok. `SendMessageTimeout` (`SMTO_ABORTIFHUNG`, 500 ms) asılı explorer'da UI kilitlemesini önler. Gizli/overflow ikonlar aynalanamaz (yalnızca açık popup'ta var) → `Win+B`. |
| Windows 11 25H2'de tepsi aynası boş | Klasik `ToolbarWindow32` tepsi 25H2'de kaldırıldı (`TrayNotifyWnd` altında `SysPager`/`ToolbarWindow32` yok; ikonlar XAML composition'da). `FindToolbarHwnd()` boş → `TrayMirrorService` UIA fallback'e düşer. UIA çocukları yalnızca taskbar `SW_SHOW` iken görünür → okuma `BeginTrayPeek(stealth:true)` (cloak + ekran dışı) gerektirir; tam `SW_HIDE` iken boş döner. İkon: `TrayCapture.PrintWindow(PW_RENDERFULLCONTENT)` park+cloak'lı taskbar'ı çizer + buton `Image` çocuk rect'i kırpılır (gerçek ikon, flash yok; yakalama başarısızsa harf glifi). Sağ/çift tık UIA ile ifade edilemez → görünür peek + fiziksel tıklama (kısa flash, kabul). |
| Stealth peek'te görev çubuğu flaşı | UIA çocukları yalnızca `Shell_TrayWnd` `SW_SHOW` iken açığa çıkar (prob ile doğrulandı: `SW_HIDE` iken `NormalButton count=0`; **auto-hide kaydırılmış durumda da 0** — auto-hide yolu ölü). Bazı makinelerde DWM cloak reddedilir; cloak'suz park+show, explorer pozisyonu geri yazınca flaşlar. Ayrıca birincil çubuk gösterilince explorer ikincil çubukları **asenkron** senkron-gösterir — reaksiyon peek temizliğinden SONRA düşebilir, per-peek stil geri yükleme o geç show'ları görünür kılar. Model: **kalıcı stealth stili** — `WS_EX_LAYERED \| WS_EX_TRANSPARENT + alpha 0` tüm tray hwnd'lerinde WharfBar boyunca kalır (`EnsureTrayStealthStyles`, idempotent; yeni ikincilleri de yakalar); görünürlük yalnızca görünür peek (`SetTrayVisible(true)` → `ClearStealthVisuals`) ve çıkışta restore edilir. Taşıma/boyutlandırma YOK (`SetWindowPos` tek başına senkron tetikler). |
| Çoklu ekranda arka plan ayarı bir bar'da tutmuyor | Dekompile edilmiş WPF-UI 4.3.0 gerçekleri: `ResourceDictionaryManager.UpdateDictionary` URI karşılaştırmaz — **her** `ApplicationThemeManager.Apply` çağrısı sözlüğü yeniler ve `WindowBackgroundManager.UpdateBackground(Application.MainWindow, …)`'ı çalıştırır; `RemoveBackdrop` → `RestoreContentBackground` MainWindow'unu opak boyar (`CompositionTarget.BackgroundColor = SystemColors.WindowColor`). **backdrop=None iken bu opak boya temizlenmez.** Yani herhangi bir pencerenin Tint/Transparent uygulaması birincil barı (MainWindow) opak bırakır. Eski kodda `ApplyTranslucent` clobber olayını hiç tetiklemiyordu → birincil yanlış, ikincil doğru kalırdı. Düzeltme üçlü: (1) `EnsureApplicationTheme` — `GetAppTheme()` aynıysa global Apply'i tamamen atla (mod/opacity değişimlerinde clobber yok); (2) `ApplyTranslucent` da clobber olayını tetikler, yalnızca güncel MainWindow işler (herkesin işlemesi ikincil↔ikincil sonsuz özyineleme üretir); (3) ayar sayfalarının doğrudan library apply'ları (tema/vurgu; default backdrop=Mica basar!) sonrası `ApplyTopBarChanges` ile tüm barlar yeniden onaylanır. |
| Tray ikonu tıklaması yanlış uygulamaya gidiyor | Snapshot poll arasında buton sırası kayarsa (ikon ekle/kaldır) index eski kalabilir; sonraki 1.5 sn poll düzeltir. Çift tık: WPF ilk tıklamada `MouseLeftButtonDown`'ı da yükseltir → forward edilen sıra `down/up, down/up, dblclk/up` olur (native `down,up,dblclk,up`); uygulamalar fazladan down/up'ı yok sayar. |
| Aynalanan ikona tiklayinca hichbir sey görünmemesi / menünün alt kenarda açılması | Uygulama flyout/menüleri gerçek `Shell_TrayWnd`'ye ankrajlidir; çubuk görünmezken InvokePattern hiçbir şey olmamış gibi durur. Tıklama akışı: görünür peek (`BeginTrayPeek(stealth:false)`) → `TaskbarNative.TryMoveTrayNear(imleçX, topBarAltY)` ile gerçek çubuk top barın hemen altına taşınır (orijinal rect kaydedilir) → settle → sol: UIA `Invoke`; sağ/çift: buton rect'i taşımadan SONRA yeniden okunur + `SendInputMouse` → menü top barın yanında açılır. Bekleyici: foreground pid == uygulama pid iken peek tutulur (min 1,5 sn, max 20 sn), ardından `RestoreMovedTray` + `EndTrayPeek`. |
| Mirror ikonlarının 1-2 sn kaybolup geri gelmesi | Her peek Shell'in XAML içeriğini yıkıp kurar; SW_SHOW sonrası beklemeden okunan ağaç boş/kısmi döner ve mirror bir tur için silinirdi. Düzeltme: okumadan önce 160 ms settle; üst üste en fazla 2 boş UIA okumasında son iyi snapshot yayında kalır, 3. boşta gerçekten temizlenir. |

## Geliştirme ipucu

AppBar ile uğraşırken sık crash olursa asılı alan normaldir. Görev Yöneticisi’nden Windows Explorer’ı yeniden başlatmak genelde düzeltir. Kalıcı çözüm yine doğru `ABM_REMOVE` ve yeniden kayıt yoludur.
